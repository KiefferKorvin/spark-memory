# Retrieval and self-enrichment

The semantic model decomposes each query into unique information needs. Query embeddings, fulltext matches, labels/aliases and neighborhood signals produce bounded candidates before navigation. Neo4j candidate generation consults both native indexes and the current graph neighborhood. Imported taxonomy concepts become candidates only once content is ABOUT them, so thousands of empty thesaurus entries cannot absorb the node budget. Common English/French question words are ignored in lexical matching. Jev never receives the whole graph.

The supervisor uses a priority heap and schedules at most `MAX_PARALLEL_BRANCHES` workers. Each branch carries a parent ID, need, current node, route, depth, score, status and evidence. Scheduling reserves `(query_id, need_id, node_id)` so shared subgraphs are not re-explored for the same need. A node may be explored for distinct needs. Global node budget reservations happen before dispatch, preventing parallel budget overshoot. Child and depth limits apply separately. Exhausted, merged, pruned and dead-end paths are observable.

Evidence is original text from a document leaf, chunk or supported assertion. Summaries route but are not passed off as original evidence. A separate relevance call checks contribution to a need. Evidence retains source records, document IDs, URI, section paths, timestamps, author, confidence and contradictions. Duplicate evidence IDs merge their need coverage. Contradictory assertion counterparts are included when encountered.

Context selection round-robins across needs, includes contradictory counterparts, deduplicates and bounds the entire serialized evidence context including provenance. Oversized text may be truncated and is marked in provenance. Coverage is evaluated against exactly this deliverable context, not an unbounded set of retrieved passages. Each need is COVERED, PARTIAL or MISSING with valid evidence references. Only all-covered yields SUFFICIENT.

When gaps remain, `EXTERNAL_RETRIEVERS` (default `wikipedia,pubmed,web`; empty disables) are searched concurrently for each missing need, and their results are interleaved so every backend contributes. Wikipedia returns lead sections, PubMed titles and abstracts (NCBI E-utilities), and web search uses DuckDuckGo's HTML endpoint with the same public-address fetch protection as URL ingestion. All are keyless. Each source is relevance-checked, then ingested concurrently with summaries and embeddings; its taxonomy concept linking finishes in the background so the waiting query does not pay for classification. Exploration then starts directly at the new documents with a fresh node budget, keeping the visited set. Defaults allow one external round and six sources. Every step is traced (`EXTERNAL_SEARCH_STARTED/EMPTY/FAILED/SKIPPED`, `EXTERNAL_SOURCE_FOUND/REJECTED` with a reason, `SOURCE_INGESTION_STARTED`, `SOURCE_INGESTED`). Unavailable external data leaves explicit insufficient coverage. The offline `demo` mode keeps its synthetic retriever.

The final model receives the question, coverage and bounded evidence—not traversal traces. The answer must cite at least one supplied evidence ID inline; returned `evidence_ids` are exactly the known IDs it cites (other bracketed text is ignored). Coverage may cite any supplied evidence for any need, since a passage found for one need can answer another. Invalid parts of a verdict are discarded conservatively (invented IDs support nothing, an unassessed need stays MISSING) without discarding the valid verdicts. Navigation-provider failure falls back to a bounded candidate order with an explicit MODEL_FAILURE event. Coverage failure conservatively stays insufficient. Synthesis failure in any mode returns original evidence excerpts rather than failing the query. Query decomposition/provider failures and timeouts produce a failed query record.

`ENRICHMENT_POLICY=on_demand` (default) requires the enrichment endpoint; `frequent` enriches retrieved leaves once successful retrievals meet the configured threshold. Quotes and contradiction targets are validated; assertion writes are atomic, and repeat enrichment is idempotent. No previous assertion is overwritten.
