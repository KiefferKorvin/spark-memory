# Ingestion

1. Validate exactly one input: UTF-8 text, base64 binary content, or an allowlisted HTTPS URL. Size and MIME limits apply to all routes.
2. Identify Source, hash original bytes, sanitize filename metadata, preserve author, URI and timestamps. No upload filename becomes a filesystem path.
3. Reuse existing document identity for duplicate content, preserving additional origins.
4. Extract text. HTML preserves headings and excludes executable content and page chrome (nav, footer, aside, forms); text in a mislabelled encoding is decoded with replacement characters rather than rejected; email includes header provenance; JSON stays structured readable text. DOCX preserves heading styles and table order. PDF extracts plain text; pages are marked with `<!-- page N -->` comments (not headings, so pages never become sections) and blank pages are skipped. Binary parsing runs in a subprocess with a 30-second timeout and Linux resource limits.
5. Parse Markdown headings and dotted numbered headings of arbitrary depth; a numbered line counts as a heading only when it starts with a capital and is not a sentence (`2.5 times higher…` stays body text). Code fences are not headings. Short coherent unsectioned documents remain retrieval leaves. Sectioned or larger documents create contextual chunks. Paragraph/sentence/whitespace boundaries precede token-bounded Unicode slicing. A configurable document/section safety limit prevents excessive work.
6. Generate summaries and distinct routing summaries bottom-up. Semantic understanding produces source type, language, temporal scope and candidate concepts. Children’s summaries are used for parent understanding; nodes of equal height are summarized concurrently. Very broad parent input is bounded; original text remains in leaves.
7. Resolve each distinct concept once per document using exact label, aliases, hybrid candidates and model judgment with graph neighbors; independent concepts are classified concurrently. Taxonomy candidates (at most 20) interleave two searches: fulltext over the concept label and its broader labels (not the free-text description), where words labelling more than 0.5% of thesaurus entries are dropped and singular/plural forms both match, and, once the thesaurus is embedded (`python -m graph_memory.unesco --embed`, resumable, re-embeds changed concepts or a new embedding model), a dedicated `ontology_vector` index over labels and scope notes. Thesaurus embeddings use their own property, so they never enter content retrieval. A concept that cannot be classified soundly is skipped instead of rejecting the document. Each skip is recorded with a reason code (`low_confidence`, `unknown_reuse_id`, `unanchored_reuse`, `no_parent`, `unknown_parent_id`, `no_anchor`, `provider_error`, `invalid_concept`), the model's confidence, the proposed parent or reuse IDs with labels, and the number of candidates shown. The records persist per document in the `classification_review` MemoryRecord (key: document ID), one WARNING line summarizes them per document, and the ingest result counts them. Only equivalent concepts are reused. New concepts can have several broader and related links. `OntologyService.align()` accepts explicit external system identifiers from applications.
8. Embed retrievable text and routing descriptions with a separately configured embedding model. The source and document hierarchy are saved in one transaction, then concepts and ABOUT links in a second one (deferred to the background for sources fetched during a query). Identical content is serialized per document; different documents ingest concurrently.

No assertions are extracted during basic ingestion. The enrichment endpoint or frequent-retrieval policy performs deeper extraction later, validates verbatim supporting quotes and retains contradiction edges.

Built-in parsing does not claim universal format support: OCR, audio/video, password-protected files, and layout-perfect PDF heading detection require application adapters. PDF numbered headings can be recovered from extracted text; PDF visual hierarchy is not inferred reliably from typography. Applications may transform arbitrary sources into text/JSON and retain their original URI in metadata. Parser and prompt versions explicitly scope identities/cache entries.
